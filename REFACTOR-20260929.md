# Refactor — batch 1 (2026-09-29)

Two real incidents from 2026-09-19/20 motivated this batch, and both are now
covered by regression tests:

* `orbgen` was invoked on an AiiDA-assembled reference tree and **silently
  started a reference DFT** — `SIAB.abacus.utils.DuplicateCheck` compares the
  whole INPUT, and the assembled one came from the AiiDA plugin (`suffix aiida`,
  no `out_wfc_lcao`), so SIAB classified every folder as new work.
* a spillage run produced `U_gga_10au_100Ry_4s3p2d2f1g.orb` whose header said
  `Number of Gorbital--> 0` — the file name promised a g channel the file did not
  have (`vloc_aux` written where SIAB ignores it), and the report only checked
  file extensions.

No git repository existed, so the pre-change tree is in
`.refactor-backup-<timestamp>.tar.gz` and the two deleted modules are in
`_removed-20260929/`.

## Batch 2 — done

**Grid point directory naming unified.** The workflow used `lmax4_rcut10p0` while
the report layer used `lmax4_rcut10` for the same point, which also meant one
spelling appeared in `static.dft_roots` keys and the other in run trees. Both now
call `interfaces.nsw.point_dir_name()`; the legacy spelling is still *read*
(`point_dir_aliases()`), so trees written before today keep resolving.

**`advanced.py` is gone.** Its three unique capabilities were ported into the
live grid search first:

| capability | how it is expressed now |
|---|---|
| `stop_on_first_valid` | new `Bool` input (default `True`); `False` makes the `iterative` strategy run the whole grid and then choose, which was previously impossible |
| explicit candidates | new `List` input `[[l_max, r_cut], ...]` (`_grid.build_explicit_grid`), for filling gaps in an already-scanned grid; mutually exclusive with `l_max_candidates`/`r_cut_candidates` |
| `max_l_max` / `max_r_cut` | honoured at last (`_grid.cap_grid`): `with_default_abacus` always forwarded them, only `advanced.py` read them |

Its per-*system* ΔE comparison was deliberately not ported (everything else uses
per-atom).

**`batch.py` split** (1754 → 1372 lines), verified by an equivalence check on the
WorkChain specs (inputs / outputs / exit codes / outline identical before and
after):

| module | contents |
|---|---|
| `workflows/batch.py` | the two WorkChain classes only (orchestration) |
| `workflows/_grid.py` | `GridEntry`, grid construction, caps, stopping rule |
| `workflows/siab.py` | `run_siab_pipeline` calcfunction, `build_abacus_child_inputs`, `n_atoms_from_stru` |
| `workflows/results.py` | the four output-`Dict` calcfunctions |

A structural test now enforces that the WorkChain module contains no SIAB call
(`generate_all_from_json(`, `read_stru(`, `subprocess`).
